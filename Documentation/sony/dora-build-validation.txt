Physical RPM implementation
---------------------------
S4/L12/L13/L20/L21 use qcom-rpm-physical.c through the existing native bank,
real PM8994 descriptors and supply phandles. Literal uv/ma/swen keys follow
Sony4.4 0c295b15b6d0fb59a64e13b9e0ef2070818ef2a1: UV in microvolts,
load in truncated milliamps saturated at8191, SWEN0/1. All five final Sony
resources use BOTH qcom,set3; no AO/floor mode is guessed for these rails.
The core aggregates consumer voltage/load/enable; system load is added once.
New regulator_sync_load replays aggregate load under the real core lock.

Registration sends no physical request. Typed readiness before retaining
consumer state permits deferred retry until the whole bank is activated.
First enable requires explicit voltage and load. Initial get_voltage returns
ENODATA, is_enabled returns the documented unknown-status EINVAL; neither
fabricates the boot voltage or OFF. Successful transactions require real
correlated transport ACKs for ACTIVE and SLEEP. Known baseline, pending
request and quarantine are separate. Any uncertain write latches the first
error, attempts only a known baseline rollback, and stays quarantined.
Explicit recovery replays an existing BOTH baseline; an unknown initial
transaction has no invented zero baseline. Failed bank resume keeps every
resource frozen until a successful complete ACK pass. PM/removal/mutation
use bank-to-resource locking; final-rdev references keep callback data alive.

Shared endpoint/type/id claims cover native/corner/physical frontends.
Attempted writes retain bounded tombstones across removal/reprobe, with
transport/node/module references. Reprobe cannot reset uncertainty or steal
another owner. Native callbacks also validate selectors/loads, wait on their
lock for outstanding writes, reject offline requests and hold final-rdev
lifetime. Builtin native parent handles may retain an inert registration on
retirement to avoid the old core freeing an upstream handle prematurely.
Pure-legacy module hotremove and generic registration-failure supply cleanup
remain unqualified outside this builtin Dora opt-in scope.

The original five rails and their resource ancestors have no Linux electrical
input edge. Their input dependencies are delegated to RPM, as the original
Sony driver does. The inherited upstream L20/L21 2.95V -> S5 2.15V dependency
was therefore removed, without guessing another Vin or creating a dummy
regulator. S4 provider always-on was removed; source eMMC IO retention remains
a consumer policy. References/hashes: dora-rpm-physical-dt.json and binding.
ACK means RPM processed a request; it does NOT measure a physical voltage,
settling, temperature, current, or the behavior of firmware on a phone.

L20=2.95V,HPM570000uA; S4=1.8V,HPM325000uA with retained IO/HPM policy.
MMC requires typed readiness before bus/clock/MMIO bootstrap. Enabled load,
voltage and enable operations force current aggregate BOTH ACKs; an enable
reference is recorded before a post-enable ACK can fail. Even cache-hit,
already-on and runtime-resume skip paths cannot bypass this gate.

Clock/NoC/pinctrl prerequisites precede timing/DLL changes. A failure stops
SDCLK and latches the first host fault, publishes no successful clock, and
blocks request, command and CQE dispatch. Power IRQ clear/pin/voltage/wait,
restore, DLL and SDCLK timeout errors feed the same latch. Uncleared IRQ
sources are masked; IRQs are not reenabled after failed restore. Fault cleanup
never accesses a gated controller and retains uncertain rail ownership.
Backend recovery alone cannot clear the host fault or reconcile its counts.

clock-provider links establish SDHC->GCC->CX ordering, supplementing real
regulator child/parent and NoC/RPM links. Normal-phase bank replay would run
later than host resume_early and permanently fault the host; the test rejects
