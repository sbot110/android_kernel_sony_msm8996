Implemented and connected
-------------------------
clk-msm8996-cpu-hw.c reads the real QFPROM NVMEM speedbin cell before APCC
clock publication. It releases the NVMEM handle/buffer, propagates deferred
probe and read failures, rejects bins4..7 and missing/malformed selected
plans, and validates all selected PWR/PERF/CBF pairs with the production
transaction engine's plan validator. No bin0 fallback is permitted. The
three plans are device-managed; partial failure frees every allocated plan.
The observer reports the selected bin without claiming a measured voltage.

Sony clock-cpu-8996.c:140-141,1330-1331 reads EFUSE[31:29] at0x74130.
The dormant native cell had reg=<0x130 4>,bits=<29 3>. Linux4.19's
Documentation/devicetree/bindings/nvmem/nvmem.txt requires a byte-relative
bit offset0..7, and nvmem_shift_read_buffer_in_place() operates on bytes.
The corrected reg=<0x133 1>,bits=<5 3> describes exactly the same fuse bits.
The adapter consumes the already-extracted one-byte value, without a second
shift. This does not change any Sony frequency/voltage table or fuse value.
The gated GPU child shares the same cell. Its existing byte-wise read_plan
accepts a one-byte extracted bin; check-variants.py now strictly validates
the corrected binding and also rejects the old offset/bits fixture. The
first clean pipeline exposed that stale checker; its failure is retained
separately from the subsequent corrected clean run.

Sony pre_set_rate moves off ACD before a voltage increase; post_set_rate
restores the ACD output after a decrease. Native CCF's voltage calculation
precedes PRE_RATE_CHANGE. Attaching voltage classes or a notifier to the
observer would violate that ordering. The existing transaction engine is
still the coordination layer, with no bound modifying callbacks. Its domain
guard must exclude both clusters' shared supply owners and power collapse;
an object mutex or stable double sample does not provide that exclusion.
CBF/ACD/PLL writes, voltage votes, suspend/resume and recovery remain OFF.
CPU_FREQ=n, CPU_IDLE=n, maxcpus=2. No SDM845 limits or fictitious providers.
