# 10. Остаточные блокеры и план натурной валидации на устройстве (`F8131` / `F8132`)

Настоящий документ перечисляет все объективно сохраняющиеся технические блокеры и зоны обязательной натурной проверки после завершения Этапов A–F адаптации и полной сборки ядра **Linux 5.15.220** (`kernel-5.5`) для **Sony Xperia X Performance (`dora`: `F8131` / `F8132`, SoC Qualcomm MSM8996)**.

В соответствии с инженерной дисциплиной проекта ни один компонент без подтверждённого лога с реального телефона не объявляется `RUNTIME VERIFIED`, а отсутствующие в mainline 5.15 аппаратные драйверы не маскируются драйверами-пустышками.

---

## 1. Архитектурные блокеры на стыке ядро 5.15 ↔ аппаратные блоки и проприетарный userspace Sony 4.4 / LineageOS

### 1.1. Подсистема камер (23 МП Sony IMX300 + 13 МП фронтальная камера) — **АРХИТЕКТУРНЫЙ БЛОКЕР (НЕ РЕАЛИЗОВАНО)**
- **Техническая причина:** В стоковом ядре 4.4.302 (`0c295b15b6d0`) камеры работают через проприетарный стек Qualcomm `msm_camera_v4l2` (`drivers/media/platform/msm/camera_v2`: `msm_isp`, `msm_cpp`, `msm_fd`, кастомный гибридный автофокус Sony и закрытый демон `mm-camera-daemon` + `libmmcamera_imx300.so` в `/oem`). В Linux 5.15 этот стек отсутствует и заменён mainline-подсистемой `qcom-camss` (V4L2 Media Controller + `libcamera`), в которой:
  1. Отсутствует драйвер эксклюзивного сенсора Sony IMX300 и его калибровочного EEPROM/PDAF;
  2. Старый Camera HAL Sony не совместим с топологией Media Controller `camss`.
- **Текущая защита в ядре 5.15:** Напряжения регуляторов `pm8994_l17` (`2.2 В`) и `pm8994_l27` (`1.0 В`) жёстко ограничены по спецификации Dora, чтобы исключить подачу завышенного напряжения базовой платформы `tone` (`2.5 В` / `1.2 В`) на модули камеры.

### 1.2. Зарядка АКБ, Fuel Gauge (`PMI8994` / `PMI8996` SMBCHG + FG) и аппаратный OTG на открытом разъёме Micro-USB — **ПРОБЕЛ ДРАЙВЕРОВ MAINLINE 5.15**
- **Техническая причина:**
  1. В апстримном Linux 5.15 отсутствуют драйверы контроллера зарядки Qualcomm `qcom,pmi8994-smbchg` (`0x1000`) и топливомера `qcom,pmi8994-fg` (`0x4000`) для PMIC PMI8994 / PMI8996 (существующий в 5.15 драйвер `qcom_smbb.c` поддерживает только более старые PM8941).
  2. На базовом уровне безопасности 5-вольтовая зарядка от USB контролируется аппаратным автоматом PMIC (OTP-профиль + инициализация загрузчика Sony S1), а термисторы `flash_therm` (`0x14`), `msm_therm` (`0x73`) и `emmc_therm` (`0x74`) выведены в `pm8994_vadc`. Однако в `/sys/class/power_supply/` отсутствуют узлы `battery` и `usb`, необходимые Android Health HAL для отображения процента заряда (`SoC`), тока, напряжения и управления быстрой зарядкой. Фиктивный `power_supply` намеренно не создавался во избежание маскировки реальной телеметрии и тепловых ограничений заряда.
  3. Для открытого влагозащищённого разъёма Micro-USB (`dora` capless USB) режим периферийного устройства (`ADB` / `MTP` / `RNDIS` через `dwc3` `dr_mode = "peripheral"`) полностью готов, линия `gpio24` переведена в безопасный `output-low` (защита от электрохимической коррозии влажных контактов), а канал `0x39` (`usb_id_lv`) добавлен в `pm8994_vadc`, но для автоматического переключения в режим USB Host OTG потребуется портирование логики периодического аналогового опроса Sony ID-VADC.
- **Путь решения:** Портирование открытых mainline/postmarketOS драйверов `qcom_smbchg` + `qcom_fg` (PMI8994/PMI8996) с параметрами батареи Dora (`float-voltage-mv = 4300..4350`, профили Sony FG).

### 1.3. TrustZone QSEE (`/dev/qseecom`) — влияние на FPC1145, Keymaster и Gatekeeper — **БЛОКЕР USERSPACE / TEE**
- **Что реализовано в ядре 5.15:** Драйвер `somc-dora-platform.c` полностью реализует ядерную сторону контракта `fpc1145_platform.c` из Sony 4.4 (`/dev/fingerprint`, магическое число `0x45`, команды `FPC_IOCWPREPARE`, `FPC_IOCWRESET`, `FPC_IOCWAWAKE`, `FPC_IOCRIRQ`, `FPC_IOCRIRQPOLL`, GPIO 21 reset, GPIO 132 level-high IRQ `IRQF_NO_AUTOEN`, регуляторы `pm8994_l18` + `pm8994_s4` без утечки тока в простое).
- **Что остаётся блокером:** В апстримном Linux 5.15 есть низкоуровневый драйвер `CONFIG_QCOM_SCM=y`, но отсутствует символьный интерфейс `/dev/qseecom` (`drivers/misc/qseecom.c`). От `/dev/qseecom` зависят не только проприетарный HAL отпечатка `fingerprint.msm8996.so` (общающийся с TZ-апплетом по защищённой шине SPI0), но и стоковые проприетарные модули аппаратной криптографии `keystore.msm8996.so` (Keymaster) и `gatekeeper.msm8996.so` из `/oem` / `/vendor`.
- **Путь решения:** Портирование совместимого с 5.15 драйвера `qseecom` (либо использование программного AOSP Keymaster/Gatekeeper на этапе первичного bring-up экрана и ADB, без ослабления SELinux и криптографии ядра).

### 1.4. Графический стек Adreno 530 (`DRM/MSM` против `KGSL`) — **ТРЕБОВАНИЕ К КОНФИГУРАЦИИ ROM**
- **Техническая причина:** Ядро 5.15 использует открытый драйвер `CONFIG_DRM_MSM=y` (`adreno_a5xx` + `a530_zap.mdt`, `/dev/dri/renderD128` и `/dev/dri/card0`). Проприетарные блобы Qualcomm от ветки 4.4 (`libGLES_adreno.so`, `vulkan.msm8996.so`) требуют отсутствующий `/dev/kgsl-3d0`.
- **Путь решения на стороне LineageOS 21/22:** Сборка открытого стека **Mesa3D Freedreno (`freedreno` OpenGL ES 3.2 + `turnip` Vulkan 1.1+)** совместно с `drm_hwcomposer` и `minigbm_msm`.

### 1.5. Аудиомаршрутизация Q6DSP / WCD9335 Tasha (ALSA UCM против legacy Audio HAL)
- **Техническая причина:** В ядре 5.15 звуковая карта регистрируется через `qcom,apq8096-sndcard` (`MultiMedia1..3` + `SLIM Playback/Capture` на `wcd9335`), где названия маршрутов микшера отличаются от проприетарного `msm8996-tasha-snd-card` из 4.4.
- **Путь решения:** Подключение профилей ALSA UCM (`HiFi.conf` / `VoiceCall.conf` для Sony Tone/Dora) в дереве устройства LineageOS 21/22.

## 2. Подсистемы Этапа F, требующие обязательной натурной проверки на реальном аппарате (`F8131` / `F8132`)

Даже после успешной полной сборки `vmlinux` и `Image.gz-dtb` (0 ошибок, 0 предупреждений) следующие аппаратные взаимодействия требуют подтверждения по `dmesg` и `ramoops` (**`0xa7f00000`**, размер `1 МБ`) на физическом устройстве:

1. **Контракт загрузчика Sony S1 (`boot.img` 64 МБ):**
   - Выбор S1 нужного `.dtb` из 4 конкатенированных вариантов (`v2.x/v3.0` × `PMI8994/PMI8996`) в `Image.gz-dtb` (13 МБ);
   - Распаковка `ramdisk.cpio.xz` и монтирование `/system` и `/oem` (`vendor` SquashFS) по раннему DT `fstab`.
2. **Питание SoC, RPM Voltage Corners, тактирование GCC/MMCC и Kryo CPUFreq/CPUIdle:**
   - Стабильность переключения углов напряжения (`qcom-rpmpd`) и частот кластеров Kryo Silver (1.59 ГГц) / Gold (2.15 ГГц) через `qcom-cpufreq-nvmem` + `cpufreq-dt` + `qcom-apcc-msm8996`;
   - Безошибочный вход и выход из состояний CPUIdle / SAW2 (`qcom_spm`) без зависаний CBF/L2.
3. **Внутренний накопитель eMMC 5.1 (`sdhc1` @ `7464900.sdhci`) и гибридный слот `F8132` (`sdhc2`):**
   - Калибровка строба HS400 (`mmc0: new HS400 MMC card`) после аппаратного сброса `GCC_SDCC1_BCR`;
   - Корректное переключение `uim2-gpios` (GPIO 29) между SD-картой и второй Nano-SIM (`SIM2`) на модели `F8132`.
4. **Совместный suspend/resume In-Cell панели и тачскрина Clearpad S3320:**
   - Отсутствие артефактов и зависаний I2C6 при гашении/пробуждении всех 5 вариантов матриц (`AUO ID4`, `JDI ID6`, `LGD ID8`, `Sharp ID3`, `Sharp ID9`) как при `wakeup_gesture=0` (полное снятие `pm8994_l22` + `panel_tvdd`), так и при `wakeup_gesture=1` (удержание питания для двойного тапа).
5. **Android 14 / 15 `init`, `lmkd` (PSI) и `bpfloader` (BTF для LOS 22):**
   - Подтверждение по `logcat -b all` старта сервисов Android 14/15; при сборке под LineageOS 22 — обязательное включение `ENABLE_BTF=1` (требует `pahole` на сборочном хосте).

## 3. Протокол первого безопасного запуска на устройстве (без риска потери рабочего состояния)

1. Выполнять первичный тест без перезаписи раздела `boot` во флеш-памяти (при поддержке `fastboot boot` конкретной версией S1 на аппарате):
   ```bash
   fastboot boot boot-dora-5.15.220.img
   ```
   *(Если загрузчик S1 на конкретном экземпляре требует `fastboot flash boot`, перед прошивкой обязательно иметь под рукой проверенный рабочий `boot.img` для немедленного возврата).*
2. При перезагрузке или ранней остановке загрузить рабочий `boot.img` с поддержкой `pstore`/`ramoops` по штатному адресу Tone/Dora **`0xa7f00000` (`0x100000`)** и сохранить посмертный журнал ядра 5.15:
   ```bash
   adb shell cat /sys/fs/pstore/console-ramoops-0 > dora-5.15-firstboot-ramoops.log
   adb shell cat /sys/fs/pstore/dmesg-ramoops-0 >> dora-5.15-firstboot-ramoops.log
   ```
